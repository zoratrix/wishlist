# Обновления для уже развёрнутого сайта

Короткие инструкции для администратора уже работающего сайта: что изменилось,
нужно ли что-то делать с базой и как обновить контейнер. Свежие записи — сверху.

**Как обновляться всегда:** в папке проекта на сервере выполнить
`./deploy/update.sh` (это `git pull --ff-only` + `docker compose up -d --build`).
Если обновление делается вручную — те же две команды по очереди.

---

## 2026-11-24 — Тонкие чёрные рамки и шапка без цветной полосы

**Что изменилось.**
- Шапка вишлиста, панель категорий, карточки подарков и таблица теперь в
  тонкой чёрной рамке, как кнопки (раньше была светлая/цветная).
- У шапки вишлиста убрана цветная полоса сверху. Цвет темы остаётся в фоне
  страницы, кнопках и мягких подложках.

**Что с базой.** Ничего: миграций нет, схема не меняется.
**Как обновить.** `./deploy/update.sh` (или `git pull --ff-only` +
`docker compose up -d --build`), затем Ctrl+Shift+R.

---

## 2026-11-24 — Чистые пастельные цвета и подложки под тему вишлиста

**Что изменилось.**
- Палитра готовых цветов (категории и темы вишлистов) стала светлее и чище:
  коралловый, персиковый, янтарный, зелёный, бирюзовый, синий, фиолетовый,
  розовый.
- Чипы категорий получили непрозрачную пастельную подложку: фон страницы и
  эмодзи-оформление больше не просвечивают сквозь них.
- В оформлении вишлиста «жёлтые» элементы (ценники в карточках, строка
  добавления подарка, номера строк и подсветка строки при наведении) теперь
  окрашиваются оттенком выбранной темы, если тема задана.

**Что с базой.** Нужна миграция `010_pastel_palette.sql` — она применяется
автоматически при старте контейнера (`docker-entrypoint`). Миграция перекрашивает
только старые 8 пресетов в `categories.color` и `wishlists.theme_color`;
`NULL` и произвольные цвета (свой `#RRGGBB`) не трогаются. Перед обновлением
можно сделать бэкап базы (папка `data/` на сервере).

**Как обновить.** Как обычно:
```bash
git pull --ff-only
docker compose up -d --build
```
После обновления — Ctrl+Shift+R в браузере.

## 2026-11-24 — Визуальные исправления (телефон и узкое окно)

**Что изменилось.**
- В таблице подарков кнопки действий больше не сжимаются: «Забронировать»
  целиком помещается в колонке, у занятого подарка компактная кнопка
  «Отменить» (полная подпись осталась для скринридеров).
- Шапка вишлиста стала непрозрачной белой, как карточки: фон страницы и
  эмодзи-оформление сквозь неё больше не просвечивают. Цвет темы остался в
  верхней полосе и рамке.
- В мобильной версии меню «Лента / Подписки / Профиль» теперь второй строкой
  в шапке; нижней фиксированной панели больше нет.
- В мобильной таблице название подарка показывается до двух строк, а кнопки
  бронирования и отмены — компактнее.

**Нужно ли что-то в базе.** Нет. Миграций нет, схема БД не меняется.

**Как обновить.** Те же две команды:
```bash
git pull --ff-only
docker compose up -d --build
```
После обновления — Ctrl+Shift+R в браузере (мог закэшироваться старый JS).

## 2026-11-24 — Кнопки «Профиль» и «Подписаться» на публичном вишлисте

**Что было не так.** Друг открыл присланную ссылку на вишлист: имя владельца
видно, но перейти в его профиль и подписаться было нельзя.

**Что изменилось.**
- В шапке публичного вишлиста появился блок владельца: аватар, имя, @логин,
  кнопка **«Профиль»** (открывает `/u/:username`) и кнопка
  **«Подписаться» / «Вы подписаны»** (повторный клик отписывает).
- Гость, нажимая «Подписаться», попадает на страницу входа и после входа
  возвращается на тот же вишлист.
- Если владелец закрыл профиль, кнопок нет — имя остаётся, чужие данные не
  раскрываются.
- Сервер: `GET /api/w/:shareToken` теперь возвращает поле
  `viewer: { isSelf, isFollowing, canFollow }` (отношение смотрящего к
  владельцу). Правила те же, что у публичного профиля.

**Нужно ли что-то в базе.** Нет. Миграций нет, схема БД не меняется; `.env`,
`data/` и загруженные картинки не трогаются.

**Как обновить.**
```bash
cd /путь/к/проекту
./deploy/update.sh
```
или вручную:
```bash
git pull --ff-only
docker compose up -d --build
```

**Как проверить после обновления.**
1. `docker compose ps` — контейнер `app` в статусе `running`.
2. Откройте чужую ссылку вишлиста в режиме инкогнито: в шапке должны быть
   аватар и имя владельца, кнопки «Профиль» и «Подписаться».
3. Войдите вторым аккаунтом и нажмите «Подписаться» — кнопка станет
   «Вы подписаны», владелец увидит нового подписчика в `/app/followers`.
4. Если видите старую версию — жёсткое обновление страницы (Ctrl+Shift+R):
   браузер мог закэшировать старый JS.

**Если что-то пошло не так.**
- Логи: `docker compose logs -f app`.
- Белый экран после обновления: пересобрать `docker compose up -d --build`,
  затем Ctrl+Shift+R в браузере.
- Откат: `git log --oneline` → `git checkout <предыдущий-коммит>` →
  `docker compose up -d --build`. Базу откатывать не нужно — схема не менялась.
