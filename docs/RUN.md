# Как запустить проект на своём компьютере

Инструкция для новичка: каждый шаг — с ожидаемым результатом и подсказкой, что
делать, если что-то пошло не так. Первый запуск занимает 15–25 минут, потом —
одна команда.

> Если вы уже настроили проект раньше — переходите сразу к шагу 9 («Запуск»).

---

## 0. Что понадобится

- Компьютер с Windows 10 или 11.
- Интернет — только для первого скачивания (дальше сайт работает без него).
- Права обычного пользователя (права администратора нужны только для установки
  Node.js).

Отдельно **не нужно** устанавливать базу данных, сервер, Docker и т.п. —
база данных SQLite создаётся сама в виде файла.

Что вы получите в итоге: сайт по адресу `http://localhost:3000` и сервер,
который живёт на этом же адресе.

---

## 1. Установить Node.js

**Зачем:** это программа, которая запускает и сайт, и сервер.

1. Откройте https://nodejs.org/ru
2. Нажмите кнопку **LTS** (не «Current») — Windows Installer (`.msi`).
3. Запустите скачанный файл. Нажимайте **Next → Next → Next → Install → Finish**.
   Ничего менять не нужно; галочка «Add to PATH» должна остаться включённой.
4. **Перезагрузите компьютер**, если установщик этого не потребовал (это
   гарантирует, что команды `node` и `npm` станут видны в терминале).

**Проверка:**

1. Нажмите `Win + R`, напишите `cmd`, нажмите Enter — откроется чёрное окно
   (командная строка).
2. Напишите `node -v` и нажмите Enter. Должно появиться примерно `v24.21.0`.
3. Напишите `npm -v`. Должно появиться примерно `11.19.0`.

**Если появилось «node не является внутренней или внешней командой»:**
перезагрузите компьютер. Не помогло — переустановите Node.js, проверив, что
пункт про PATH включён.

---

## 2. (По желанию) Установить Git

**Зачем:** история изменений кода и возможность откатиться. Без Git проект
работать будет, но сохранять версии станет сложнее.

1. Откройте https://git-scm.com/download/win — скачайте *64-bit Git for Windows
   Setup*.
2. Запустите, оставьте все настройки по умолчанию, нажимайте **Next → Install**.
3. В командной строке выполните `git --version` — должна появиться версия,
   например `git version 2.56.0`.

---

## 3. (Позже, для писем) Mailpit

Понадобится на этапе уведомлений — это локальный «почтовый ящик», в котором
видны письма, отправленные сайтом (реальным людям они не уходят).

1. Откройте https://mailpit.axllent.org/docs/install/
2. Скачайте архив для Windows (`mailpit-windows-amd64.zip`), распакуйте,
   например, в `C:\Tools\mailpit`.
3. Запустите `mailpit.exe`. Веб-интерфейс писем: http://localhost:8025

Сейчас этот шаг можно пропустить.

## 4. Открыть папку проекта в терминале

**Самый простой способ:** в папке проекта дважды щёлкните файл **`start.cmd`** —
он сам перейдёт в нужную папку, при необходимости создаст базу и запустит сайт,
а затем откроет браузер. Окно с текстом закрывать нельзя — это и есть работающий
сайт.

**Если запускаете вручную:**

1. Откройте «Проводник» (Explorer) и зайдите в папку проекта — ту, где лежит
   файл `package.json` и документы (`ARCHITECTURE.md` и т.д.).
2. Нажмите в адресной строке, напишите `cmd` и нажмите Enter — откроется
   командная строка **в этой папке**. (Или: Shift + правый клик по пустому
   месту → «Открыть окно PowerShell здесь».)
3. Проверьте, что вы в нужной папке: выполните `dir` — в списке должен быть
   `package.json`.

> **Частая ошибка:** команда выполнена в `C:\Users\User` (или другой папке) — в
> ответ появляется `npm error Missing script: "dev"`. Это значит, что терминал
> открыт не там. Перейдите в папку проекта командой
> `cd /d D:\harness_workshop\wishlist` (подставьте свой путь) и повторите.

Дальше все команды выполняются **в этом окне**.

## 5. Установить зависимости

Выполните:

```
npm install
```

**Что происходит:** скачиваются библиотеки, из которых собран сайт и сервер.
Это занимает 1–3 минуты и требует интернета.

**Ожидаемый результат:** сообщение вида
`added 229 packages, and audited ... found 0 vulnerabilities`.

**Если ошибка `EPERM` или `spawn ... EPERM`** (обычно из-за антивируса или
блокировки файлов):

1. Повторите команду ещё раз.
2. Если повтор не помог — обновите npm: `npm install -g npm@latest`, затем снова
   `npm install`.
3. Временно отключите антивирус на время установки, затем включите обратно.
4. Крайний вариант: `npm install --ignore-scripts` (в нашем проекте
   native-модуль базы данных содержит готовый бинарник, поэтому установка без
   сборочных скриптов работает).

**Если `npm` не найден** — вернитесь к шагу 1.

---

## 6. Настроить файл `.env`

Файл `.env` хранит локальные настройки и секреты. В проекте уже есть образец —
`.env.example`.

1. В «Проводнике» включите показ расширений файлов: вкладка «Вид» →
   поставьте галочку «Расширения имён файлов».
2. Скопируйте `.env.example` и переименуйте копию в `.env`
   (в командной строке: `copy .env.example .env`).
3. Сгенерируйте два секрета. В командной строке выполните:

```
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

Скопируйте выведённую строку. Откройте `.env` Блокнотом (правый клик →
«Открыть с помощью» → «Блокнот») и замените `replace_with_long_random_string`
на эту строку. Сохраните.

4. Выполните команду ещё раз, получите **второй** (другой) секрет и замените им
   `replace_with_another_random_string`.

5. Проверьте остальное (менять обычно не нужно):

```
APP_URL=http://localhost:3000
DATABASE_PATH=./server/data/app.db
PORT=3000
```

Сохраните файл. **Никому не пересылайте `.env`** и не загружайте его в Git —
он уже исключён через `.gitignore`.

---

## 7. Создать базу данных

Выполните:

```
npm run db:migrate
```

**Что происходит:** создаётся файл базы `server/data/app.db` со всеми таблицами.

**Ожидаемый результат:** строка
`INFO  Применены миграции: 001_init.sql`.

**Если появилось «Не удалось прочитать настройки (.env)»** — вы пропустили шаг
6 или файл называется иначе (например, `.env.txt`).

**Если появилось «database is locked»** — закройте другие окна с проектом
(возможно, сервер уже запущен).

---

## 8. Добавить тестовые данные

Выполните:

```
npm run db:seed
```

**Ожидаемый результат:** строки
`INFO  Тестовые данные созданы.` и данные для входа:

- `anna@example.com` / `test12345`
- `boris@example.com` / `test12345`

(Логины пригодятся на этапе 2, когда появится вход.)

---

## 9. Запустить сайт

Выполните:

```
npm run dev
```

**Что происходит:** запускается один процесс, который отдаёт и сайт, и API.

**Ожидаемый результат:** примерно такие строки (порядок и мелочи могут
отличаться):

```
INFO  Сайт и API запущены: http://localhost:3000
INFO  Режим: разработка (Vite + Express в одном процессе)
```

Откройте браузер и введите `http://localhost:3000` — должна открыться страница
«Вишлисты» с заголовком **«Проект запущен»** и двумя зелёными отметками
(«Сервер» и «База данных»).

**Важно:** пока это окно терминала открыто — сайт работает. Не закрывайте его.

---

## 10. Остановить сайт

1. Щёлкните по окну терминала, где запущен проект.
2. Нажмите `Ctrl + C` (иногда нужно дважды; если спросят «Завершить пакетный
   файл (Y/N)?» — нажмите `Y`).
3. Если сайт всё ещё открывается, проверьте, кто занял порт:

```
netstat -ano | findstr :3000
```

В последнем столбце будет номер процесса (PID). Остановите его:

```
taskkill /PID <номер> /F
```

---

## 11. Запустить снова

В папке проекта выполните ту же команду:

```
npm run dev
```

Данные никуда не делись: база лежит в `server/data/app.db`.

## 12. Проверить, что всё в порядке (по желанию)

| Команда | Что делает | Ожидаемо |
|---|---|---|
| `npm test` | запускает автотесты сервера и сайта | `Tests 8 passed` и `Tests 3 passed` |
| `npm run typecheck` | проверяет типы TypeScript | без ошибок, код 0 |
| `npm run build` | собирает сайт в `web/dist` | `✓ built in ...` |
| `npm start` | запуск собранной версии (сначала нужен `npm run build`, порт 3000 должен быть свободен) | та же страница, но уже «как на сервере» |

## 13. Где смотреть ошибки

1. **Терминал**, где запущен `npm run dev`: красные строки `ERROR` или стек
   вызовов — почти всегда там.
2. **Браузер:** нажмите `F12` → вкладка **Console** (ошибки JavaScript) и
   **Network** (запросы к `/api`, их коды ответа).
3. **База данных:** файл `server/data/app.db` можно открыть программой
   [DB Browser for SQLite](https://sqlitebrowser.org/) — она бесплатная.
4. Если сервер не запускается, его последнее сообщение обычно прямо говорит,
   чего не хватает (например: «База данных не готова. Выполните npm run
   db:migrate»).

## 14. Обновление зависимостей (не обязательно)

Делайте это не чаще раза в месяц и **отдельной задачей**, а не «заодно»:

1. `npm outdated` — список устаревших пакетов.
2. Обновляйте по одному: `npm install -w server имя@версия --save-exact`.
3. После каждого обновления: `npm test` и `npm run build`.
4. Если что-то сломалось — верните предыдущую версию (Git: `git checkout -- .`).

Автоматическое обновление «всего сразу» может сломать проект — не делайте так.

---

## 15. Сохранять изменения (Git)

После того как что-то поправили (или агент поправил):

```
git status
```

Проверьте список — там **не должно быть** `.env`, файлов базы, `node_modules`,
`CONTEXT.md`, `AGENTS.md`, `TODO.md` (они уже в `.gitignore`). Затем:

```
git add .
git commit -m "Короткое описание, что изменилось"
```

История: `git log --oneline`.

---

## 16. Начать с чистыми данными

**Внимание: это удалит все данные в базе.**

1. Остановите сайт (`Ctrl + C`).
2. Удалите файлы базы: `server/data/app.db`, а также `app.db-wal` и
   `app.db-shm`, если они есть.
3. Снова выполните: `npm run db:migrate`, затем `npm run db:seed`.

## 17. Типовые проблемы и решения

| Симптом | Причина | Что делать |
|---|---|---|
| `npm error Missing script: "dev"` | Команда выполнена не в папке проекта | `cd /d D:\harness_workshop\wishlist` (свой путь), затем `npm run dev`. Или дважды щёлкните `start.cmd` |
| `Порт 3000 уже занят` | Сайт уже запущен в другом окне терминала | Закройте старое окно с сайтом и запустите снова. Если не помогло: `netstat -ano \| findstr :3000` → `taskkill /PID <номер> /F` |
| `'node' не является внутренней или внешней командой` | Node.js не установлен или не попал в PATH | Переустановить Node.js, перезагрузить компьютер |
| `npm install` падает с `EPERM`/`spawn` | Антивирус, блокировка файлов, права | Повторить; отключить антивирус на время; `npm install --ignore-scripts` |
| `Не удалось прочитать настройки (.env)` | Нет файла `.env` или в нём ошибка | Выполнить шаг 6; проверить, что оба секрета заменены |
| `База данных не готова. Не применены миграции` | Не выполнен `npm run db:migrate` | Выполнить `npm run db:migrate` |
| `EADDRINUSE: port 3000` | Порт занят другим процессом | `netstat -ano \| findstr :3000` → `taskkill /PID <pid> /F`, либо сменить `PORT` в `.env` |
| Страница открывается, но пустая | Ошибка JavaScript | F12 → Console; перезапустить `npm run dev` |
| Вижу старую версию страницы | Кэш браузера | `Ctrl + F5` |
| Сайт не открывается по `localhost:3000` | Сервер не запущен / другой порт | Проверить терминал; открыть `http://127.0.0.1:3000` |
| Всё очень медленно работает | Папка в OneDrive/сетевом диске, антивирус | Перенести проект в локальную папку (например, `D:\proects\wishlist`), добавить её в исключения антивируса |
| `node --watch` падает с `spawn EPERM` | Редкое ограничение среды | Запускать без авто-перезапуска: `node --disable-warning=ExperimentalWarning server/src/dev.ts` |
| Файл `.env` не видно | Скрытые расширения | «Вид» → «Расширения имён файлов» |
