# Развёртывание «Хотелок» на своём сервере

Ниже — рабочий вариант для домашнего сервера (проверялось на Synology NAS
с Container Manager) за домашним роутером. Архитектура максимально простая:
**один Docker-контейнер** с приложением и один том с данными.

```
Интернет → роутер (проброс 443) → Synology (обратный прокси, HTTPS) → контейнер :3000
```

## 1. Что нужно

- Сервер/NAS с поддержкой Docker (Synology DSM 7 → **Container Manager**).
- Постоянный IP внутри сети у сервера (в роутере — статический DHCP-адрес).
- Домен или DDNS-имя (можно бесплатный DDNS от Keenetic/Synology), чтобы был HTTPS.
- 1 ГБ свободной памяти и ~1 ГБ диска (плюс место под фото/обложки).

## 2. Быстрый запуск (5 команд)

Скопируйте папку с проектом на сервер (например, `/volume1/docker/hotelets`),
затем по SSH:

```bash
cd /volume1/docker/hotelets

# 1) Настройки
cp .env.example .env
# сгенерируйте два разных секрета и вставьте их в .env:
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"

# 2) Сборка и запуск
docker compose up -d --build

# 3) Проверка
docker compose ps
curl http://127.0.0.1:3000/api/health
```

Сайт откроется по адресу `http://IP-сервера:3000`. Зарегистрируйте первый
аккаунт и создайте вишлист.

## 3. Файл `.env` — что обязательно заполнить

| Переменная | Значение |
|---|---|
| `APP_ORIGIN` | полный адрес сайта, например `https://hotelets.example.com` |
| `SESSION_SECRET` | случайная строка (48 байт, base64url) |
| `HASH_SECRET` | другая случайная строка |
| `TZ` | ваш часовой пояс, например `Europe/Moscow` |
| `SMTP_*` | почта для писем со сбросом пароля (можно позже, см. отдельную инструкцию) |

`DATABASE_PATH` и `UPLOAD_DIR` в Docker заданы в `docker-compose.yml`
(`/data/app.db` и `/data/uploads`) — менять не нужно.

> **Важно:** сохраняйте `.env` в кодировке UTF-8 и с переводами строк LF.
> Если редактировали файл в Блокноте Windows и что-то «сломалось»:
> `sed -i 's/\r$//' .env`

## 4. Данные и бэкапы

Всё состояние — в папке `./data` рядом с `docker-compose.yml`:

- `data/app.db` — база SQLite (вишлисты, подарки, брони, пользователи);
- `data/uploads/...` — аватары и обложки.

Резервная копия вручную:

```bash
./deploy/backup.sh                 # создаст backups/hotelets-ДАТА.tar.gz
./deploy/restore.sh backups/ФАЙЛ.tar.gz
```

В Synology: **Панель управления → Планировщик задач → Создать задачу**
(еженедельно, от пользователя root):

```bash
cd /volume1/docker/hotelets && ./deploy/backup.sh
```

Обязательно копируйте папку `backups/` ещё куда-нибудь (облако, внешний диск,
Hyper Backup) — бэкап на том же диске не спасает от поломки диска.

## 5. Обновление версии

```bash
cd /volume1/docker/hotelets
./deploy/update.sh
```

Миграции базы применяются автоматически при старте контейнера.

## 6. Домашний роутер Keenetic Giga (1012)

1. **Статический адрес NAS.** В Keenetic: *Список устройств → Synology →
   Зарегистрировать постоянный адрес* (например, `192.168.1.50`).
2. **Проброс портов:** *Дом. сеть → Переадресация портов*:
   - `443` → `192.168.1.50:443` (HTTPS, если делаете обратный прокси на NAS);
   - при проверке без HTTPS можно временно `3000` → `192.168.1.50:3000`
     (потом лучше закрыть).
3. **DDNS:** *Интернет → DDNS* — включите Keenetic DDNS (или свой домен
   у регистратора). Получите имя вида `xxxx.keenetic.pro`.
4. **Проверка портов открывается ли:** из мобильного интернета откройте
   `http://IP-из-DDNS:3000` (или https после шага 7).

> **Если у провайдера CGNAT** (частный IP в интернете, часто у мобильных и
> некоторых домашних тарифов), порты снаружи не работают. Варианты:
> попросить у провайдера «белый IP», либо Cloudflare Tunnel / Tailscale —
> тогда проброс портов и DDNS не нужны.

## 7. HTTPS (рекомендуется) — на самом Synology

Docker-контейнер отдаёт HTTP на `:3000`, а сертификат удобнее держать в DSM:

1. *Панель управления → Вход и безопасность → Сертификат* — получите
   сертификат Let's Encrypt (нужен домен/DDNS и открытый 80-й порт).
2. *Login Portal → Advanced → Reverse Proxy*: создайте правило
   `https://hotelets.example.com` → `http://127.0.0.1:3000`.
3. В `.env` укажите `APP_ORIGIN=https://hotelets.example.com` и перезапустите:
   `docker compose up -d`.
4. В роутере оставьте проброшенными `80` и `443` на NAS.

## 8. Полезные команды

```bash
docker compose ps                     # статус
docker compose logs -f app            # логи приложения
docker compose restart app            # перезапуск
docker compose down                   # остановить (данные останутся в ./data)
docker compose up -d --build          # пересобрать после обновления кода
```

## 9. Частые проблемы

| Симптом | Что проверить |
|---|---|
| Сайт не открывается снаружи | проброс портов в роутере, белый IP (не CGNAT), firewall NAS |
| `502` от обратного прокси | контейнер не запущен: `docker compose ps`, `docker compose logs app` |
| «База данных не готова» | контейнер не смог применить миграции — смотрите логи, проверьте права на `./data` |
| Не приходят письма | SMTP в `.env`, порт 587/465, см. отдельную инструкцию по SMTP |
| Фото не загружаются | лимит `MAX_UPLOAD_MB`, свободное место, права на `./data` |
| После обновления белый экран | жёсткое обновление в браузере (Ctrl+Shift+R), пересборка `--build` |

## 10. Безопасность — минимум перед «боевым» использованием

- Оставьте режим «только по ссылке/подписчикам» по умолчанию для приватных списков.
- Не публикуйте `.env`, папку `data` и бэкапы.
- Включите автоматические обновления DSM и регулярные бэкапы.
- Если сайт открыт в интернет — обязательно HTTPS и надёжные пароли.
- Для публичного сервиса в РФ могут действовать требования 152-ФЗ (персональные
  данные) — это отдельная юридическая работа, не входит в техническое развёртывание.
